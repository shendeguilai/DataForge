# 可达 OJ 作业跟踪

登录 DataForge，从“实用工具 → 可达 OJ 作业跟踪”进入。每位教师的连接设置、班级、名单、作业和更新任务独立保存，学生不需要 DataForge 账号。

实用工具首页不再展示教师工作台。原有班级、作业、学生和考试数据保留，从对应工具进入管理。

保存 SID 后，服务器每分钟检查一次是否到期：距上次身份验证约半小时后发起一次只读身份请求，尝试维持 OJ 会话活跃；与每天零点的作业更新独立，关闭网页仍会执行。连接页显示最近身份检查时间和结果。网络失败不会清除已保存的 SID；明确返回未登录时暂停心跳，重新录入并验证成功后恢复。清除凭据后不再发送请求。心跳不能延长 OJ 的绝对有效期，也不能绕过主动退出、账号封禁等上游规则。

## 首次使用

1. 在“OJ 连接”录入可达 OJ 的纯 SID，或包含 `sid` 的 Cookie。默认题库域为 `system`，对应主站；其他域填写域标识。
2. 保存时验证 OJ 身份。凭据使用现有 `DATAFORGE_SECRET` 加密，前端不回显。不要改变生产环境的加密密钥，否则旧凭据无法解密。
3. 在“学生名单”创建班级，每行输入“姓名, OJ UID”，先查询并核对 OJ 用户名，再确认添加。每次、每个班级最多 500 人。
4. 新建周作业，填写班级、题号、域和开始时间。默认截止时间为 7 天后，可修改，每份作业最多 100 题。显示题号保留前缀和前导零，指向相同内部题号的输入自动去重。
5. 点击“手动更新”。后台查询无需保持页面打开；重新打开页面可继续查看进行中的任务。创建作业本身不会查询提交记录。

班级名单之后的修改、移出和重命名不会改写已创建作业保存的名单与班级名称。旧作业仍按原名单统计。

## 完成判定

- 同一域、同一题目存在可见 AC 即完成，包含开始前和比赛内的 AC；统一显示 `AC`。
- 以首次 AC 那条记录的**提交时间**判定是否补交；截止时间采用不包含结束时刻的边界。在截止时刻或之后提交并 AC，显示 `AC · 补交`。提交在截止前、评测在截止后仍算截止前完成。
- 后续 WA 不会覆盖已存在的 AC。日常更新检查新增记录，每 7 天完整复核历史；“更新选项 → 完整复核历史记录”可以立即核对历史重测或删除造成的变化。
- 部分分数且未 AC 显示“尝试中”，排队/编译/评测中的记录显示“评测中”，完整查询未发现记录显示“未见提交”。自测和数据生成记录不计入。
- 查询失败、权限不足或分页异常显示“待核验”，保留上次结果、已完成数和成功更新时间；这些旧结果会标明“上次 AC”。不能据此判断学生没有提交。
- 点击题目状态查看提交次数、最高分、最近提交、首次 AC、来源和 OJ 记录链接。打开链接需要浏览器自身拥有 OJ 访问权限。

## 日常操作

- **编辑作业**：可修改名称、时间、题号和域，保留创建时的学生名单。截止时间改变会重新判定补交；同域保留未删除题目的结果，新题或更换域后需要更新。更新中的作业暂不能编辑，归档作业需先恢复。并发修改会提示重新打开编辑。
- **复制作业**：预填原题单，时间默认后移 7 天，可选择目标班级。副本按目标班级当前名单创建，完成结果独立保存，不改动原作业。
- **未完成清单**：点击“复制未完成清单”，预览或修改文字后复制。已确认待完成和待核验分开列出；不会自动发给学生或家长。
- **每题统计**：题目表头显示已确认 AC 人数，点击表头可查看已完成、待完成和待核验的学生分组。
- **学生总览**：点击学生姓名，查看该学生在各班级、各份作业（含归档）中的完成和补交情况，并可跳回原作业。待完成和待核验总计只包含已开始、未归档作业。
- **本次更新变化**：显示新增确认完成、其中补交的题次，以及复核后历史 AC 失效的变化。首次核验单独标记，不将其描述为学生刚完成；仅表示本次查询确认的变化。
- **导出 Excel**：下载包含“班级完成表”“每题统计”“待完成清单”三个工作表的 `.xlsx` 文件，保留完整题号和 UID。待核验旧 AC 单独标明；导出数据不会再次请求 OJ。
- **失败重试**：失败项显示原因并保留上次结果。可“只重试失败项”，不重复查询本份作业中已成功的单元格；首次尚未查询的作业使用“手动更新”。

## 更新与运行

默认每天北京时间 **00:00** 将已经开始且未归档的作业加入更新队列。可在 OJ 连接设置中改为“仅手动更新”。服务在零点停机时不补跑，等待手动更新或下一个零点。日期输入和展示均使用北京时间，不受服务器 UTC 设置影响。

点击更新后，按钮旁立即显示提交提示；后台开始后显示正在核验的学生与题目、已处理项数、百分比和用时。进度按“学生 × 题目”逐项推进，完整核验一题的所有记录后才计为处理完一项，保存结果时最多显示 99%，任务结束才显示完成。更新中禁止重复提交；关闭或刷新页面后可恢复查看后台任务。进度连接临时中断会显示重连提示并自动重试，不会将后台任务误判为结束。

截止后持续跟踪补交，直到手动归档。归档保留当前结果并停止更新；恢复后可再次手动更新。已在执行中的任务不会覆盖归档结果。

同一教师只有一个活跃更新任务；定时和手动更新重叠时合并目标作业，任务内复用相同域、学生和题目的查询。每位教师的所有 OJ HTTP 请求串行执行，相邻请求至少间隔一秒。最多同时执行两位教师的任务。

任务和租约持久化在数据库中，进程重启后排队任务可继续，执行中任务在 120 秒租约到期后重新查询。首次查询、凭据变更、已有评测中记录、距上次完整核验满 7 天及手动完整复核均读取完整历史，分页从第一页读到空页。其余更新读到已知记录 ID 所在页，将已验证的增量按 ID 合并到缓存；旧记录的远期重测、删除最迟在下次完整复核发现。每页校验学生、域、内部题号、页码及记录顺序。重复页、无法确认的筛选、超过 10000 页或其他异常均不作为完整结果。一次查询中前面已成功的项保留，后续失败项标记待核验。

后台固定请求 `https://kedaoi.cn`，仅使用 GET，不跟随重定向，不抓取学生代码，不写入 OJ。主域使用 `/api/user`、`/api/problem` 和 `/record`；独立域加 `/d/<domain>`。查询记录启用 `all=true` 以包含比赛记录，因此 OJ 账号需具备相应记录与比赛可见权限。403 仅提示权限问题，不直接判断 Cookie 过期；游客身份、限流、网络失败和响应结构错误分别提示。

查询指定学生使用 `/api/user?args={"id":3847}&projection=_id,uname`（实际请求进行 URL 编码）。UID 必须保留 JSON 数字类型，直接传 `id=3847` 会被当前 OJ 的参数校验拒绝。HTTP 400/422 单独提示查询参数被拒绝，不显示为站点不可用。

## 开发与部署

- 新页面：`/kedaoj-homework.html`；API 前缀：`/api/tools/kedaoj-homework`。页面和 API 均需登录。
- API 包括 `settings`、`settings/verify`、`settings/credential`、`classes`、`students/preview`、班级学生增改删、`assignments`、作业编辑（带 `revision`）、`copy/incomplete/export.xlsx/refresh/retry-failed/archive/restore`、`students/{uid}/overview`、`tasks/active` 和任务状态查询。`refresh?full=true` 请求完整复核。
- 更新接口返回 HTTP 202 与任务 ID；任务状态包括 `QUEUED`、`RUNNING`、`SUCCEEDED`、`PARTIAL`、`FAILED`。设置响应仅包含是否配置、身份和状态，不包含凭据或密文。
- 新增 Flyway `V8__kedaoj_homework.sql`；生产部署沿用现有 PostgreSQL/Flyway 流程。开发环境 H2 由 JPA 创建数据表。
- 数据持久化于 `kedaoj_homework_records`，按类型保存连接设置、班级、作业及名单快照、提交摘要和同步任务。无需额外外部服务或这台 Mac 的 SID 代理。
- 编辑版本、统计变化和增量缓存元数据均保存在已有 JSON 载荷内，兼容旧作业；升级后首次查询会自动补建完整历史缓存，无需额外数据库迁移。
- `dataforge.homework.scheduling-enabled=false` 可在自动化测试中关闭定时入队及后台任务派发；正常运行保留默认 `true`。
- 运行模块测试：`mvn -Dtest='cn.datacraft.homework.*Test' test`。HTTP 查询使用本地模拟 OJ；真实 OJ 联调需要教师自行录入有效凭据及目标学生/题单，不在测试中读取 Mac 钥匙串。
