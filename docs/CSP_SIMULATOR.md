# CSP 复赛模拟：使用与部署

## 教师使用

登录 DataForge，在“实用工具 → CSP 复赛模拟 → 教师控制台”进入。

1. 添加学生，或上传 UTF-8 CSV。列名为 `姓名,班级,学号`，班级可省略。学号在本教师名单中唯一，允许重名。学生直接使用姓名和学号进入，不再生成随机进入码。学号按文本保存，保留前导零。停用档案会禁止访问；“退出所有设备”可撤销该学生的已登录会话；修改姓名或学号也会撤销旧会话。
2. 新建考场，选择 Linux / Windows、教学 / 模拟考试、学生名单、时长和题目。每场最多 60 名学生、10 道题。地区代码默认 `GD`，模拟准考证号默认按“地区代码-组别学号”生成，例如学号 `10002` 对应 `GD-J10002` / `GD-S10002`，学号前导零原样保留，不按名单顺序重新编号；老师可修改地区代码，并逐人修改准考证号和答案文件夹名。
3. 默认答案根目录为 Windows 的 `D:\` 或 Linux 的桌面 `/home/noi/Desktop`，考生文件夹使用准考证考号。例如 `D:\GD-J10002\task1\task1.cpp` 或 `/home/noi/Desktop/GD-J10002/task1/task1.cpp`。本工具使用按学号生成的模拟准考证号训练，真实比赛按[目标考区通知](https://noi.ccf.org.cn/gs/xw/gd/2025-10-25/850192.shtml)和实际准考证填写；Linux 桌面是本工具的训练预设。也可选择“地区代码-名单学号”（`{region}-{studentNumber}`）、自定义答案根目录和命名规则。规则支持 `{examNumber}`、`{region}`、`{name}`、`{studentNumber}`，需要拼音时逐人填写自定义文件夹名。新默认用于新建考场；已有未开考场可用“按学号更新考号和目录”重新生成考号及按命名规则生成的文件夹名（会替换逐人自定义的文件夹名），不移动文件，已开考场保持原配置；正式训练以目标考区当年通知为准。
4. 每题可上传评测数据 ZIP、多选配对的 `.in/.out/.ans` 文件（合计最多500MB；ZIP展开后也最多500MB），或选择自己已完成的数据工坊任务。支持同一目录内同名 `.in/.out` 或 `.in/.ans`；缺失、重复、两种答案同时存在均拒绝导入。本站数据包中的题面、标准程序等不会作为测试点。上传时显示实际传输进度，传完后继续校验并保存，完成后才提示成功。大数据分段写入磁盘，不整体加载到内存。上传后可以查看数据清单；128KB以内支持只读预览，较大的文件下载查看。隐藏数据预览和下载均校验考场归属。
5. 确认数据分值。逐点模式每行填写本点得分；子任务模式填写组名，同组每行填写相同的整组分值。每题总分必须等于该题满分。换数据后需重新确认。样例通过独立入口上传，学生能查看；完整隐藏数据不会下发学生，成绩发布后只展示个人失败测试点的有限输出差异片段。
6. 系统生成唯一的六位纯数字考场编号，也可复制加入链接。已有考场自动补充短编号，旧加入链接仍可使用。通知学生后开考。到时自动锁定；也可提前结束统一收卷。
7. 收卷后发起评测，查看批次进度。服务故障显示“待重试”，不产生学生分数，未完成批次不能发布或导出正式成绩。重测保留旧批次，老师选择发布其中一批。
8. 在“文件与记录”查看交卷清单、只读源码，也可选错误位置的代码进行复盘。复盘批次不能作为正式成绩发布。源码包保留每位学生的原始虚拟路径及 manifest，不会自动修正目录。
9. 评测详情显示首个不一致的行、列，以及预期输出和学生输出的附近片段；行末空格与文末换行仍被忽略。文件输出缺失、异常退出和资源超限显示具体原因。旧批次没有诊断时，需重新评测。
10. 未开考时可编辑完整配置和学生名单；收卷后可编辑题目、时限、内存及输入输出方式，然后重测。修改满分后需要重新确认分值。进行中需先结束收卷。
11. 收卷后“重新开始”准备新一轮，保留六位考场编号、旧交卷副本及评测批次，将本轮工作区重置为空。可先编辑名单、题目或环境，再点击“开始考场”重新计时。旧轮次不能发布为本轮成绩，学生仍可查看旧轮次已发布成绩。

## 学生使用

学生在本机编写代码，通过考场链接，或输入六位数字考场编号、姓名和学号进入。相同凭证可在换电脑后恢复自己的工作区；新的登录会使旧登录失效。进入后保存考场会话并更新地址，刷新或重新打开学生入口会恢复上次考场及目录。网络故障不会清除会话；主动切换学生、教师撤销会话或身份变更后需要重新进入。

- 学生必须自己建立考生目录与题目目录。系统只准备答案根目录及桌面位置，不创建正确答案文件夹。
- 支持创建文件夹、重命名、移动、删除、上传多个文件和整个文件夹。可以将文件或文件夹拖到左侧目录树、列表中的目标文件夹、上一级按钮或当前目录空白处进行移动；目标同名时拒绝覆盖，不能移入自身或自身子目录。拖入文件夹时保留层次结构。上传覆盖保留目标现有拼写；调整大小写须使用重命名。
- 代码、输入、输出等可只读预览；页面不提供代码编辑或学生自行评测。文件保存成功后才计入工作区。一个文件最多 2MB，工作区最多 1500 个项目、25MB；一次上传最多 200 个文件、25MB。
- 教学模式可随时检查目录；模拟考试结束后开放检查。Linux 文件操作区分大小写，Windows 操作不区分大小写，但正式收卷要求与规定路径的拼写完全一致。
- 可重复交卷，最后一次交卷作为最终答案。交卷后改动而未重新交卷，不会覆盖已交卷副本。到时从未交卷者自动收取已保存文件。
- 老师发布后显示个人每题结果、班级总分排名和历史成绩，同分并列。正式成绩中，源文件错位或缺失记该题零分；目录问题单独展示。

## 启用评测服务

网页文件功能无需 Docker Worker，但真实判题必须在 Linux Docker 主机上启用独立 Worker。主应用不运行学生程序；未启用 Worker 时，有源码的评测任务保持排队。

在 `/etc/dataforge/dataforge.env` 增加：

```dotenv
CSP_SIM_ENABLED=true
CSP_SIM_WORKER_SECRET=替换为至少24字符的独立随机密钥
CSP_SIM_CONCURRENCY=2
```

使用现有 `scripts/prod.sh deploy` 构建或拉取本次版本，会同时准备 Worker 与沙箱镜像，并在主应用健康后启动 Worker。首次需要 GitHub Actions 发布 `dataforge-csp-worker`、`dataforge-csp-sandbox` 两个新镜像。镜像同步到 ACR 的流程已包含它们。关闭功能时停用 Worker；网页与已有档案仍可访问。

手动构建与启动（仓库根目录；环境文件中的 `DATAFORGE_IMAGE_TAG` 须与运行应用版本一致）：

```bash
docker compose --env-file /etc/dataforge/dataforge.env -f compose.prod.yml build csp-judge-worker csp-sandbox-image
docker compose --env-file /etc/dataforge/dataforge.env -f compose.prod.yml --profile csp-sim up -d --no-deps csp-judge-worker
```

镜像仓库模式将第一条改为 `pull csp-judge-worker csp-sandbox-image`。恢复备份或回滚时先停 Worker，待相同版本应用及沙箱镜像就绪后再启动。

Worker 使用 Docker socket 创建临时容器，因此仅可信 Worker 获得该 socket；主应用和学生容器不挂载它。Worker 没有 HTTP 监听端口，通过 `X-CSP-Worker-Key` 调用内部评测接口。密钥为空或不足24字符时接口禁用。不得把密钥放进网页、题面、学生文件或共享日志。

沙箱采用 Ubuntu 20.04，固定 G++ 9.3.0（Focal release 包），编译参数 `-O2 -std=c++14 -static`。构建和运行均验证编译器版本。学生程序运行在非 root、无网络、只读根文件系统的容器中，限制内存、CPU、进程、磁盘写入和输出；每个测试点使用全新工作区，只收到当前输入，标准答案在沙箱外比较。CPU 时间作为题目时限，另设墙钟超时；栈限制与题目内存限制一致。

程序源文件最多100KiB，编译阶段限制30秒 CPU / 40秒墙钟、512MB 地址空间、16MB 编译输出。运行输出最多16MB。编译资源不足或基础设施失败标记服务故障；编译语法错误标记 CE。训练机器性能不等同官方评测机器。

## 持久化与恢复

生产 Flyway V7 新增 `csp_sim_records`，保存各类记录、队列、租约和版本；现有用户、生成任务和其他工具的数据不受影响。学生学号以数据库唯一键保证教师范围内唯一。

源码和测试文件保存于 `DATAFORGE_RUNTIME_DIR/csp-sim/blobs`，以系统生成标识访问，虚拟路径不映射为宿主机路径。交卷与评测绑定不可变文件内容、题目配置和数据版本。现有数据库 + runtime 联合备份包含该功能的数据。学生进入不再依赖加密的随机进入码；`DATAFORGE_SECRET` 仍用于本站其他加密配置，部署时保持原值。

任务租约90秒，Worker 每20秒续租。中断后超时任务可重新领取，旧租约不能下载文件或提交结果。队列、成绩和学生凭证不会随应用重启丢失。

旧版 H2 导入器用于已有旧系统表的迁移；如果已经在新版 H2 中使用 CSP 模拟，不要用旧版导入器迁移这些档案，应迁移完整新版数据库与 runtime。

## 验证

```bash
mvn test
python3 -m unittest discover -s services/csp-sim-worker -p 'test_*.py'
```

在 Linux Docker 主机上验证真实编译、文件读写及资源限制：

```bash
docker build -f services/csp-sim-worker/Dockerfile.sandbox -t dataforge-csp-sandbox:local services/csp-sim-worker
CSP_SIM_DOCKER_TESTS=1 python3 -m unittest discover -s services/csp-sim-worker -p 'test_*.py'
```

自动发布流程先运行这些 Docker 测试，再发布评测镜像。无 Docker 的电脑会跳过四个真实沙箱测试，仍可验证服务、界面与计分规则。

## 宝塔 Linux 面板部署

宝塔负责管理网站和 Docker 环境，判题由本项目的独立 Worker 完成。宝塔面板版本不能确定宿主机发行版、CPU 架构、内存及 Docker 状态，部署前需核对这些实际配置。当前发布流程提供 Linux amd64（x86_64）镜像，宿主机使用 Docker Engine 与 Compose v2，并启用上述 CSP 配置。

可在宝塔终端执行本项目现有部署脚本，网站通过反向代理访问主应用；Worker 和学生沙箱无需开放公网端口。上传 `.cpp` 是保存答案，教师上传并确认评测数据、收卷及发起评测后才会判题。正式使用前运行上文真实 Docker 测试，核对编译器、文件输入输出和资源限制；面板能够管理容器不代表这些检查已经通过。

参考：[宝塔 Docker 官方说明](https://docs.bt.cn/category/docker)、[Docker Engine 安装说明](https://docs.docker.com/engine/install/)。

### 2 核、2GB 服务器

此规格先将 `CSP_SIM_CONCURRENCY=1`，让整班交卷进入队列串行评测。60 人同时进入、上传文件与 60 个程序同时编译是不同负载；排队不会减少题目分数。单个编译容器的内存上限为 768MB，运行容器上限为题目内存加 64MB；网站、数据库、宝塔和其他服务也需内存，因此此设置不保证 2GB 主机一定足够。

可同时在生产配置中设置 `DATAFORGE_APP_MEMORY_LIMIT=768m` 和 `DATAFORGE_JAVA_OPTIONS='-Xms128m -Xmx384m'`，给评测保留内存余量。默认不改变已有网站的内存限制；小内存配置仍应结合实际课堂负载验证。

上线前核对空闲内存、Docker 状态和 CPU 架构，运行真实编译与资源限制测试，再用整班提交量验收。出现基础设施故障时任务应保留并重试，不能计入学生零分。镜像使用现有 GitHub Actions / ACR 成品发布流程，避免在小内存生产机上编译整套应用。
